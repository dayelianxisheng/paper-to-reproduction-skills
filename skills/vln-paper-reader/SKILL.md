# VLN Paper Reader

默认快速阅读，按需深入。先判断论文价值，再投入更多阅读和计算成本。

## 选择模式

- **Fast（默认）**：用于首次阅读、批量筛选和相关性判断。即使论文很重要，也只建议下一步，不在同一轮自动升级。
- **Standard**：仅在用户要求“精读”“标准分析”或指定训练、推理、消融等内容时使用。
- **Deep**：仅在用户明确要求公式推导、代码对应、复现评估、多论文对比、创新方案或实验设计时使用；只深入用户要求的部分。

没有明确模式时使用 Fast。不要把输出长度误当作分析深度。

## 读取最小内容

Fast 优先读取：

1. 标题、摘要和基本信息；
2. 引言中定义问题与贡献的段落；
3. 方法总图及其说明；
4. 主结果表；
5. 结论。

仅在总图无法解释方法、论文主张与结果不一致，或当前模式需要时继续读取正文。Standard 增加核心方法、训练、推理和消融章节；Deep 只增加当前问题所需的公式、附录、代码或外部资料。

若来源不完整或页面无法读取，明确说明缺失证据，不凭摘要补造细节。

## 核心流程

1. **识别论文**：提取标题、年份、出处、任务类型、论文来源和已给出的代码来源；不要在 Fast 中广泛搜索相关工作。
2. **建立全局理解**：回答研究问题、核心方法、有效证据和主要限制，避免重复复述贡献列表。
3. **还原方法数据流**：按“输入 → 视觉/语言编码 → 历史或地图 → 多模态融合 → 决策 → 动作”组织。每个核心模块只说明输入、输出、作用和必要性。
4. **提取训练与推理**：训练只说明数据集、监督、主要损失、预训练和额外数据；推理只说明观测、状态更新、动作选择、停止以及搜索/回退/规划依赖。
5. **判断实验可信度**：检查提升幅度、公平性、核心消融、额外数据或更大模型、Seen/Unseen 差异及性能成本。不要逐项复述所有表格。
6. **形成研究判断**：给出主要优点、主要局限、与用户方向的关系、是否值得精读或复现，以及最合适的下一篇对比论文。无法从证据判断时标为“未说明”。

始终区分作者主张、论文证据和自己的推断。

## 分析规则

- 优先解释相对已有方法真正变化的部分，不重复讲解标准注意力、Softmax 或交叉熵。
- 核心公式解释变量、计算、作用和直觉；辅助公式一句话说明用途；常规公式除非被修改，否则跳过。
- 默认只分析方法总图、主结果、核心消融和最关键失败案例。
- Fast 中简要识别：离散/VLN-CE、视觉与语言输入、历史与空间表示、动作输出、额外依赖和部署能力。
- Standard 或 Deep 时读取 [VLN 检查表](references/vln_checklist.md)；仅在论文涉及动态环境、世界模型或在线适应时启用对应扩展项。

## 输出

Fast 使用以下短结构：

```text
# 论文概览
基本信息：
任务类型：
一句话总结：

# 方法
输入 / 输出：
核心结构：
核心创新：

# 实验
数据集与指标：
关键结果：
实验是否支持结论：

# 研究判断
优点：
局限：
与我的方向的关系：
是否值得精读：
```

Fast 控制在约 500–800 个中文字，信息不足时宁可更短。Standard 或 Deep 时读取 [输出模板](references/output_templates.md)，并删去与用户问题无关的栏目。

## 边界

- 不默认审计 GitHub 仓库、依赖、CUDA、PyTorch、Habitat、ROS、数据、权重、显存或无头运行。
- 不默认逐行分析代码、推导全部公式、生成完整复现方案或大量创新点。
- 用户要求本机复现可行性时，转交 `$evaluate-research-project`；论文内容与代码实现需要结合时，才在 Deep 中做有限映射。
- 不为阅读过程创建日志、清单或中间文件，除非用户明确要求保存。
